## Що таке Briefing?

Briefing — це настільний застосунок для нотаток, створений для команд, яким потрібна **одна спільна база знань без хмарного сервісу посередині**.

- 📝 **Пишіть** у звичайних Markdown-файлах, які лежать у звичайній папці на вашому комп'ютері (вашому «сховищі», vault).
- 🔄 **Діліться** папкою з командою: кожен комп'ютер зберігає ідентичну копію, а зміни передаються **напряму з комп'ютера на комп'ютер** із наскрізним шифруванням — за лічені секунди.
- 🧠 **Запитуйте** будь-що: кожну нотатку індексує ШІ-модель, що працює **на вашому власному комп'ютері**, а **Claude** (або будь-який MCP-клієнт) може шукати, читати й записувати нотатки через вбудований MCP-сервер.

У результаті ви з колегою можете одночасно працювати кожен зі своїм Claude над тими самими знаннями компанії й завжди бачити найновішу версію.

> Наразі інтерфейс — **бразильською португальською**. Переклади вітаються — див. [Як долучитися](../../CONTRIBUTING.md).

## Як це працює

<div align="center"><img src="../images/architecture.svg" alt="Архітектура: два комп'ютери синхронізуються напряму, кожен має локальний ШІ-індекс, який Claude читає через MCP" width="860"></div>

1. **Ви створюєте команду** і вибираєте папку. Briefing генерує код запрошення на кшталт `BRF-7Q2M-…`.
2. **Колега вставляє код.** Комп'ютери знаходять один одного через публічну DHT [Hyperswarm](https://github.com/holepunchto/hyperswarm) — вона використовується *лише* для пошуку — і відкривають пряме з'єднання, зашифроване протоколом Noise. Кожна сторона доводить, що знає код, ще до передачі першого файлу.
3. **Кожна зміна надсилається одразу**, хто б її не написав — ви, колега чи Claude. Одночасні зміни об'єднуються рядок за рядком (як у Git); якщо двоє змінили ті самі рядки, інша версія зберігається як *копія конфлікту*, однакова на всіх комп'ютерах — нічого не губиться.
4. **Кожен комп'ютер індексує нотатки локально** (багатомовні ембеддинги + пошук за ключовими словами). Claude звертається до індексу через MCP і за мілісекунди отримує найрелевантніші фрагменти.

## Встановлення

Завантажте останню версію для своєї системи з **[Releases](https://github.com/renankelm10/briefingMCP/releases)**.

| Система | Файл | Примітки |
|---|---|---|
| Windows 10/11 | `Briefing-Setup-x.y.z.exe` | Поки без цифрового підпису: у попередженні SmartScreen натисніть **Докладніше → Усе одно запустити**. |
| macOS 12+ (Apple Silicon) | `Briefing-x.y.z-arm64.dmg` | Поки без нотаризації: клацніть застосунок правою кнопкою → **Відкрити** або виконайте `xattr -dr com.apple.quarantine /Applications/Briefing.app`. Mac на Intel: зберіть із вихідного коду. |
| Linux (x64) | `Briefing-x.y.z.AppImage` / `.deb` | AppImage: `chmod +x Briefing-*.AppImage`. На Ubuntu 24.04+ краще `.deb` (`sudo apt install ./briefing_*.deb`) — він налаштовує пісочницю Chromium. |

Під час першого запуску Briefing створює приклад сховища в `Документи/Briefing`. Щоб відкрити будь-яку папку, скористайтеся **Arquivo → Abrir outro vault…**.

### Збирання з вихідного коду

Потрібен [Node.js 22+](https://nodejs.org).

```bash
git clone https://github.com/renankelm10/briefingMCP.git
cd briefingMCP
npm install
npm start            # запуск застосунку
npm run dist         # збирання інсталятора для вашої системи (у release/)
```

## Папки команди за 3 кроки

1. Відкрийте папку, якою хочете поділитися, як сховище й натисніть <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>E</kbd> (**Equipes**).
2. **Criar equipe** → код запрошення скопійовано. Надішліть його колезі приватним каналом.
3. Колега відкриває **Equipes → Entrar numa equipe**, вставляє код і вибирає порожню папку. Файли надійдуть, щойно обидва комп'ютери будуть онлайн.

Для синхронізації Briefing має працювати на обох комп'ютерах. Кожен, хто має код, стає повноправним учасником — ставтеся до нього як до пароля.

## Підключення Claude (MCP)

Відкрийте **✦ Segundo cérebro → Conectar automaticamente** або виконайте:

```bash
claude mcp add briefing --scope user -- node "/шлях/до/briefingMCP/src/mcp/server.mjs"
```

Перезапустіть Claude Code. Сервер надає доступ до відкритого сховища та всіх папок команд:

| Інструмент | Що робить |
|---|---|
| `search` | Гібридний семантичний + ключовий пошук; повертає найрелевантніші фрагменти з файлом і рядком |
| `read_note` | Повний текст нотатки (за шляхом або просто за назвою) |
| `list_notes` | Нотатки сховища чи папки з датою зміни |
| `recent_changes` | Нещодавно змінені нотатки — зокрема зміни, що надійшли від колег |
| `write_note` | Створити, перезаписати або доповнити нотатку (одразу синхронізується з командою) |
| `vault_info` | Сховища, кількість проіндексованих нотаток/фрагментів, стан семантичного пошуку |

Будь-який MCP-клієнт, що підтримує stdio-сервери, працює так само. Використовуйте `BRIEFING_VAULTS="/a;/b"`, щоб явно вибрати сховища.

## Безпека та приватність

- Без облікового запису, без сервера, без телеметрії. Нотатки — звичайні файли на вашому диску.
- З'єднання синхронізації мають наскрізне шифрування й автентифікуються кодом запрошення; файли з мережі ніколи не записуються поза спільною папкою, а виконувані файли, отримані від інших, Briefing ніколи не відкриває.
- Ембеддинги обчислюються локально; модель (`multilingual-e5-small`, ~120 МБ) завантажується з Hugging Face один раз.
- Відповіді MCP позначають вміст нотаток як недовірені дані, щоб зменшити ризик prompt injection.

Повна модель загроз — у **[SECURITY.md](../../SECURITY.md)**. Повідомляйте про вразливості конфіденційно.

## Поширені запитання

**Це Obsidian?** Ні. Briefing — незалежний проєкт із відкритим кодом, написаний з нуля. Він сумісний зі звичайними папками Markdown, тож можна відкрити наявне сховище, але проєкт не пов'язаний з Obsidian і не схвалений ним.

**Чи потрібен інтернет?** Лише щоб знайти колег (DHT) і один раз завантажити ШІ-модель. Нотатки, пошук і доступ Claude працюють офлайн.

**Що, як двоє редагують ту саму нотатку?** Різні частини об'єднуються автоматично. Якщо змінено ті самі рядки, зберігаються обидві версії: одна — у нотатці, інша — у копії `(conflito de …)` поруч.

**Де мої дані?** У папці сховища (файли `.md`). Власні дані Briefing лежать у `<vault>/.briefing/` (індекс, історія) і в папці налаштувань користувача (`%APPDATA%\Briefing`, `~/Library/Application Support/Briefing`, `~/.config/Briefing`).
