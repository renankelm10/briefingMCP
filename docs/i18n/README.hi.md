## Briefing क्या है?

Briefing एक डेस्कटॉप नोट्स ऐप है, उन टीमों के लिए जो **बीच में किसी क्लाउड सेवा के बिना एक साझा नॉलेज बेस** चाहती हैं।

- 📝 अपने कंप्यूटर के एक सामान्य फ़ोल्डर (आपके "vault") में रखी सादी Markdown फ़ाइलों में **लिखें**।
- 🔄 किसी फ़ोल्डर को अपनी टीम के साथ **साझा करें**: हर कंप्यूटर पर एक जैसी कॉपी रहती है और बदलाव **सीधे एक कंप्यूटर से दूसरे पर** जाते हैं — एंड‑टू‑एंड एन्क्रिप्टेड, कुछ ही सेकंड में।
- 🧠 कुछ भी **पूछें**: हर नोट को एक AI मॉडल इंडेक्स करता है जो **आपकी अपनी मशीन पर** चलता है, और **Claude** (या कोई भी MCP क्लाइंट) बिल्ट‑इन MCP सर्वर के ज़रिए आपके नोट्स खोज, पढ़ और लिख सकता है।

नतीजा: आप और आपका साथी एक ही समय पर, अपने‑अपने Claude के साथ, कंपनी के एक ही ज्ञान पर काम कर सकते हैं और हमेशा नवीनतम संस्करण देख सकते हैं।

> फ़िलहाल इंटरफ़ेस **ब्राज़ीलियाई पुर्तगाली** में है। अनुवादों का स्वागत है — देखें [योगदान](../../CONTRIBUTING.md)।

## यह कैसे काम करता है

<div align="center"><img src="../images/architecture.svg" alt="आर्किटेक्चर: दो कंप्यूटर सीधे सिंक होते हैं, हर एक में लोकल AI इंडेक्स है जिसे Claude MCP से पढ़ता है" width="860"></div>

1. **आप एक टीम बनाते हैं** और एक फ़ोल्डर चुनते हैं। Briefing `BRF-7Q2M-…` जैसा एक इनवाइट कोड बनाता है।
2. **आपका साथी कोड पेस्ट करता है।** कंप्यूटर सार्वजनिक [Hyperswarm](https://github.com/holepunchto/hyperswarm) DHT के ज़रिए एक‑दूसरे को ढूँढते हैं — जिसका उपयोग *केवल* खोजने के लिए होता है — और Noise से एन्क्रिप्टेड सीधा कनेक्शन खोलते हैं। कोई भी फ़ाइल भेजने से पहले दोनों पक्ष साबित करते हैं कि उन्हें कोड पता है।
3. **हर बदलाव तुरंत भेजा जाता है** — चाहे आपने लिखा हो, आपके साथी ने या किसी Claude ने। एक साथ हुए बदलाव लाइन‑दर‑लाइन मर्ज होते हैं (Git की तरह); अगर दो लोग एक ही लाइनें बदलें तो दूसरा संस्करण *कॉन्फ़्लिक्ट कॉपी* के रूप में सहेजा जाता है, जो हर कंप्यूटर पर एक जैसी होती है — कुछ भी खोता नहीं।
4. **हर कंप्यूटर नोट्स को लोकली इंडेक्स करता है** (बहुभाषी एम्बेडिंग + कीवर्ड खोज)। Claude MCP के ज़रिए इंडेक्स से पूछता है और मिलीसेकंड में सबसे प्रासंगिक अंश पाता है।

## इंस्टॉलेशन

अपने सिस्टम के लिए नवीनतम बिल्ड **[Releases](https://github.com/renankelm10/briefingMCP/releases)** से डाउनलोड करें।

| सिस्टम | फ़ाइल | नोट |
|---|---|---|
| Windows 10/11 | `Briefing Setup x.y.z.exe` | अभी कोड‑साइन नहीं है: SmartScreen चेतावनी में **More info → Run anyway** पर क्लिक करें। |
| macOS 12+ (Apple Silicon) | `Briefing-x.y.z-arm64.dmg` | अभी नोटराइज़्ड नहीं है: ऐप पर राइट‑क्लिक → **Open**, या `xattr -dr com.apple.quarantine /Applications/Briefing.app` चलाएँ। Intel Mac: सोर्स से बिल्ड करें। |
| Linux (x64) | `Briefing-x.y.z.AppImage` / `.deb` | AppImage: `chmod +x Briefing-*.AppImage`. Ubuntu 24.04+ पर `.deb` बेहतर है (`sudo apt install ./briefing_*.deb`), जो Chromium सैंडबॉक्स सेट करता है। |

पहली बार चलाने पर Briefing `Documents/Briefing` में एक उदाहरण vault बनाता है। कोई भी फ़ोल्डर खोलने के लिए **Arquivo → Abrir outro vault…** का उपयोग करें।

### सोर्स से बिल्ड करें

[Node.js 22+](https://nodejs.org) ज़रूरी है।

```bash
git clone https://github.com/renankelm10/briefingMCP.git
cd briefingMCP
npm install
npm start            # ऐप चलाएँ
npm run dist         # अपने सिस्टम के लिए इंस्टॉलर बनाएँ (release/ में)
```

## 3 चरणों में टीम फ़ोल्डर

1. जिस फ़ोल्डर को साझा करना है उसे vault के रूप में खोलें, फिर <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>E</kbd> (**Equipes**) दबाएँ।
2. **Criar equipe** → इनवाइट कोड कॉपी हो जाता है। इसे किसी निजी चैनल से अपने साथी को भेजें।
3. आपका साथी **Equipes → Entrar numa equipe** खोलकर कोड पेस्ट करता है और एक ख़ाली फ़ोल्डर चुनता है। दोनों कंप्यूटर ऑनलाइन होते ही फ़ाइलें पहुँच जाती हैं।

सिंक होने के लिए Briefing दोनों कंप्यूटरों पर चलता होना चाहिए। जिसके पास कोड है वह पूरा सदस्य बन जाता है — इसे पासवर्ड की तरह संभालें।

## Claude जोड़ें (MCP)

**✦ Segundo cérebro → Conectar automaticamente** खोलें, या चलाएँ:

```bash
claude mcp add briefing --scope user -- node "/path/to/briefingMCP/src/mcp/server.mjs"
```

Claude Code को रीस्टार्ट करें। सर्वर खुला vault और सभी टीम फ़ोल्डर उपलब्ध कराता है:

| टूल | क्या करता है |
|---|---|
| `search` | हाइब्रिड सिमेंटिक + कीवर्ड खोज; फ़ाइल और लाइन के साथ सबसे प्रासंगिक अंश लौटाता है |
| `read_note` | किसी नोट की पूरी सामग्री (पाथ से या केवल नाम से) |
| `list_notes` | किसी vault या फ़ोल्डर के नोट्स, संशोधन समय के साथ |
| `recent_changes` | हाल में बदले गए नोट्स — साथियों से आए बदलाव भी |
| `write_note` | नोट बनाएँ, ओवरराइट करें या उसमें जोड़ें (टीम के साथ तुरंत सिंक) |
| `vault_info` | vault, इंडेक्स किए गए नोट्स/अंशों की संख्या, सिमेंटिक खोज की स्थिति |

stdio सर्वर सपोर्ट करने वाला कोई भी MCP क्लाइंट इसी तरह काम करता है। vault स्पष्ट रूप से चुनने के लिए `BRIEFING_VAULTS="/a;/b"` का उपयोग करें।

## सुरक्षा और गोपनीयता

- कोई अकाउंट नहीं, कोई सर्वर नहीं, कोई टेलीमेट्री नहीं। नोट्स आपकी डिस्क पर सादी फ़ाइलें हैं।
- सिंक कनेक्शन एंड‑टू‑एंड एन्क्रिप्टेड हैं और इनवाइट कोड से प्रमाणित होते हैं; नेटवर्क से आई फ़ाइलें कभी भी साझा फ़ोल्डर के बाहर नहीं लिखी जातीं, और दूसरों से मिली एक्ज़िक्यूटेबल फ़ाइलें Briefing कभी नहीं खोलता।
- एम्बेडिंग लोकली कैलकुलेट होती हैं; मॉडल (`multilingual-e5-small`, ~120 MB) Hugging Face से एक बार डाउनलोड होता है।
- prompt injection का जोखिम घटाने के लिए MCP जवाब नोट की सामग्री को अविश्वसनीय डेटा के रूप में चिह्नित करते हैं।

पूरा थ्रेट मॉडल **[SECURITY.md](../../SECURITY.md)** में पढ़ें। कमज़ोरियों की सूचना निजी रूप से दें।

## अक्सर पूछे जाने वाले प्रश्न

**क्या यह Obsidian है?** नहीं। Briefing एक स्वतंत्र, ओपन‑सोर्स प्रोजेक्ट है जिसे शुरू से लिखा गया है। यह सामान्य Markdown फ़ोल्डरों के साथ संगत है, इसलिए आप मौजूदा vault खोल सकते हैं, लेकिन यह Obsidian से जुड़ा या उसके द्वारा समर्थित नहीं है।

**क्या इंटरनेट चाहिए?** केवल साथियों को ढूँढने (DHT) और AI मॉडल को एक बार डाउनलोड करने के लिए। नोट्स, खोज और Claude की पहुँच ऑफ़लाइन काम करती है।

**अगर दो लोग एक ही नोट एडिट करें तो?** अलग‑अलग हिस्से अपने‑आप मर्ज हो जाते हैं। अगर एक ही लाइनें बदलें तो दोनों संस्करण रखे जाते हैं: एक नोट में और दूसरा उसके पास `(conflito de …)` कॉपी में।

**मेरा डेटा कहाँ है?** आपके vault फ़ोल्डर में (`.md` फ़ाइलें)। Briefing का अपना डेटा `<vault>/.briefing/` (इंडेक्स, इतिहास) और यूज़र कॉन्फ़िग फ़ोल्डर में रहता है (`%APPDATA%\Briefing`, `~/Library/Application Support/Briefing`, `~/.config/Briefing`)।
